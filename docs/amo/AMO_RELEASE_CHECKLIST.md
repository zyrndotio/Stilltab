# Stilltab 0.8.0 — Mozilla Add-ons release checklist

**Status:** Development build only; no AMO submission, signature, approval, or public listing has been made. After the repository reorganization, all five 0.8.0 archives were rebuilt in a temporary directory and passed ZIP integrity checks; every manifest target exists in the installable packages. Firefox, Edge, and Chrome dashboard and toolbar-popup previews rendered without page errors. Focused Playwright browser-mock tests passed against the rebuilt AMO package for Chromium, Chrome's native `chrome.*`-only namespace, Firefox API simulation, onboarding/providers, RSS/stock/Sync, CSS toggling, Pomodoro editing, and RSS permission cleanup. Real installed-browser and store/reviewer work remains.

## Before submitting

1. **Complete publisher information.** Replace the maintainer/contact placeholder in [`../PRIVACY.md`](../PRIVACY.md), publish the reviewed notice at a stable public HTTPS URL, and prepare a monitored support contact. The current privacy notice is a draft, not a ready public policy.
2. **Choose and freeze the Firefox add-on ID.** The source manifest at `manifests/firefox.json` currently uses `stilltab@local.extension`. Keep it only if it is acceptable as the permanent identifier; otherwise replace it before first submission.
3. **Choose a software license.** None has been selected. Do not infer a license from the source bundle.
4. **Real Firefox testing.** On Firefox 142+ Release, test first-run and all optional data/host-consent flows; the toolbar action popup; adding, deduplicating, and removing active-tab shortcuts; current-tab title/URL behavior; cached same-origin HTTPS icon behavior, no-icon fallback, and manual shortcut input; bookmarks, crypto, RSS/stock, settings, export/import, CSS off/clear, timer editing, reset, and Firefox Sync with two desktop profiles. Confirm the `tabs` permission prompt is accurately explained and that the popup only queries the active tab. Treat Sync as desktop-focused until Android is separately tested.
5. **Real Chrome and Edge testing.** Test Chrome 121+ and Edge 136+ unpacked packages. Confirm action popup, activeTab behavior, Chromium's `favicon` permission and local `_favicon/` images, URL/title capture, no public favicon service calls, optional provider prompts, and no Chromium-wide `tabs` permission. Retest each API-dependent widget and storage persistence.
6. **Privacy and permission review.** Verify that Firefox's same-origin favicon request is user-triggered, uses `credentials: omit` and `referrerPolicy: no-referrer`, is bounded to 4 KB, and is saved locally; verify shortcut icon data is excluded from Sync. The optional Google favicon helper is not enabled by the app. Keep the Firefox `tabs` permission rationale explicit in the listing and reviewer notes.
7. **Provider terms and descriptions.** Confirm current Open-Meteo/GeoNames attribution and non-commercial API terms, Alpha Vantage key/rate/data limits, CoinGecko rate limits, and external feed/site terms. Disclose the relevant data and request IP sent by user-invoked features.
8. **Build all packages.** From the repository root, run `./scripts/build-packages.sh`. The Firefox AMO package must be `stilltab-v0.8.0-amo-upload.zip` with a root-level `manifest.json` and organized `newtab/`, `popup/`, `shared/`, and `assets/` directories; the full source archive is not the installable AMO package. Verify matching 0.8.0 manifests and that Chrome/Edge packages contain their correct permission split.
9. **AMO lint (2026-10-07, organized package).** `npx --yes web-ext lint --source-dir <extracted-AMO-package>` reported **0 errors, 0 notices, and 7 `UNSAFE_VAR_ASSIGNMENT` warnings** at `newtab/app.js` lines 627, 629, 630, 691, 919, 938, and 991. Manual inspection found dynamic search-engine/theme/widget values escaped or normalized before they reach fixed extension templates; shortcut labels are created with DOM APIs and `textContent`. These warnings still need reviewer disclosure and fresh review after each source change; do not call the package warning-free.
10. **Prepare listing details.** Select AMO-listed or self-distributed delivery; prepare name, summary, full description, category, version notes, locale, privacy-policy URL, support/homepage details, license, icons, and real screenshots. Select Firefox Desktop only unless Android was tested.
11. **Answer source-code question accurately.** The package ships authored readable JS/HTML/CSS unchanged. `scripts/build-packages.sh` only copies files and archives them, so the current answer to whether code-generating/minifying/bundling/template tools are used is **No**. Upload the AMO ZIP, not the source archive.
12. **Submit and follow review.** Use `AMO_SUBMISSION_STEPS.md`. Reviewer notes should explain no analytics, Firefox's `tabs` permission for current-tab metadata, the popup's user-invoked active-tab query, optional data/host-consent flows, same-origin favicon caching, the absence of a default public favicon service, and the optional feed/article host access. Do not claim approval until AMO signs and publishes the listing.
