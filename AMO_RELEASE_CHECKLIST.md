# Stilltab 0.7.0 — Mozilla Add-ons release checklist

**Status:** Stilltab is a development build. No AMO submission, signature, approval, or public listing has been made. Dual-browser UI/regression tests passed in mocked Chromium contexts; the generated Firefox XPI and Edge ZIP also rendered their first-run dashboard without page errors. Neither check substitutes for real Firefox/Edge testing.

## Before submitting

1. **Complete publisher information.** Replace the maintainer/contact placeholder in `PRIVACY.md`, publish the reviewed notice at a stable public HTTPS URL, and prepare a monitored support contact. The current privacy file is a draft, not a ready public policy.
2. **Choose and freeze the Firefox add-on ID.** `manifest.json` currently uses `stilltab@local.extension`. Keep it only if it is acceptable as the permanent identifier; otherwise replace it before first submission. Avoid changing it after release.
3. **Choose the license.** No license has been selected. Choose the software license you intend to grant; do not infer one from the current source bundle.
4. **Real Firefox testing.** On Firefox 142+ Release, test first-run profile selection, permissions and declines/re-consent for search/weather/RSS/article/stock/crypto, the Privacy Center, collapsible sections, custom CSS apply/off/on/clear plus migration of an existing saved style, local data/reset, Pomodoro click-to-edit with save/cancel and keyboard activation, and Firefox Sync with two signed-in desktop profiles and Add-ons sync enabled. Firefox Sync remains desktop-focused; do not claim Android support without a separate Android test.
5. **Real Edge testing.** Test the unpacked Edge build on current Edge 136+; verify its first-use provider explanations, each optional-origin prompt, consent cancellation, local bookmarks, crypto rate-limit/error states, and data persistence. Do not claim Firefox Sync in the Edge listing.
6. **Provider terms and descriptions.** Confirm current Open-Meteo/GeoNames attribution and non-commercial API terms, Alpha Vantage key/rate/data limitations, CoinGecko rate limits, and external feed/site terms before publishing. The listing must disclose that user-initiated requests send the relevant query/location/feed/ticker/key/coin ID and request IP to outside services.
7. **Validate package scope.** Run `./build-packages.sh`. Use `stilltab-v0.7.0-amo-upload.zip` for AMO's package-upload field; it has the installable Firefox files at the archive root. Keep `stilltab-v0.7.0-source.zip` as the readable full project/reviewer bundle, not as the extension package. Verify that the Firefox upload ZIP has a root-level `manifest.json` and excludes Edge-only manifest metadata.
8. **Run current lint and review warnings.** Lint the flat AMO package (rather than the full project directory, which also contains the shell packaging script): extract `stilltab-v0.7.0-amo-upload.zip` to a temporary directory, then run `npx --yes web-ext lint --source-dir <that-directory>` or Mozilla's current equivalent. The current flat 0.7 Firefox package result is **0 errors and 7 `UNSAFE_VAR_ASSIGNMENT` warnings** on dynamic `innerHTML` template renderers. Review every warning manually for escaped user text, validated URLs/IDs, and fixed markup; explain those invariants to reviewers and do not present warnings as a clean lint.
9. **Prepare listing details.** Choose AMO-listed distribution if you want a public catalog listing; choose self-distribution only if that is the intended delivery. Prepare name, summary, long description, category, version notes/changelog, locale, privacy-policy URL, support/homepage details, license, icon, and real screenshots. Select Firefox Desktop only unless Android has been tested.
10. **Answer source-code question accurately.** The current package ships the authored readable JS/HTML/CSS unchanged; `build-packages.sh` only copies files and archives them. For this build, answer **No** to the question about code generators/minifiers/bundlers/templates/processing that generate included source. Upload the flat package ZIP, not the full nested source archive, in the extension package field. If you later transform, minify, bundle, or generate code, answer Yes and submit the corresponding reproducible source/build instructions.
11. **Submit and follow review.** Use `AMO_SUBMISSION_STEPS.md` for the exact UI sequence. Add reviewer notes describing optional host/data-consent behavior, the broad but optional HTTPS origin used only for selected user-provided feeds/articles, local-only defaults, the separate Edge build, and how to reach optional widgets. Address validator/reviewer requests and do not claim approval until AMO signs and publishes the listing.
